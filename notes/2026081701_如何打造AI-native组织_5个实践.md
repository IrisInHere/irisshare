## 1. 系统组成与原理

**先破后立**：你以为 AI 落地难在"模型不够强、Prompt 写不好"？==错。讲者的原话是：今天海外和中国的模型都已经非常强，Agent 表现不好，"大概率不是他的问题，是你的问题……它是 context 的问题，是上下文的问题"。== 你花大量时间雕琢 Prompt，却没把该给的信息给到它——就像雇了个聪明实习生，却不让他看公司资料。

**核心等式（记死这一条）**：

- **AI-native = agent readable**（对 agent 可读）。把"AI-native 组织"这个词直接替换成"agent readable 组织"——企业里各种信息（沟通、会议、文档、日程、CRM）对 agent 是不是可见可读的？看不到，就没有 context，表现就不会好。
- **信息越是散落孤岛，agent 越废**。你越是把决策沉淀在群里、妙记里、口头沟通里（而不是书面文档），agent 越读不到，越表现差。所以落地的第一杠杆不是换模型，是**把信息对 agent 敞开**。

**工作方式的三次演化（理解你正处在哪一层）**：

1. **打字式工作**（直到去年主流）：人对着电脑打字。
2. **口喷式工作**（今年大部分人）：对着电脑说话、用语音输入。
3. **聊天式工作**（下一层）：你跟同事随意开着会、聊着天，agent 在旁边听着，现场就把事干了。

> 越往后越贴近人类最自然的沟通方式。关键洞察：**沟通和执行之间的距离可以被压缩到零**——"沟通即执行"。

**Agent 协作的三个段位（对照你团队在哪）**：

- **Level 1**：人跟人协作，没有 AI。
- **Level 2**：每个人跟自己的 AI 协作（AI 在 Codex/本地，人在飞书——两个界面割裂）。
- **Level 3**：AI 无缝融入人与人的协作，像同事一样在群里、在会里工作。

> 讲者判断：最 AI-native 的公司，内部 agent 不只是"个人助理"，而是**同事级别的团队 agent**——有团队级 context，能接力、能培训、有全局视角。

## 2. 五个可落地实践（逐实践：原理 + 动手清单）

### 实践一 · AI-native 会议

**核心要点速览**
- **会议 = 给 agent 最好的 context**：远比文档/知识库丰富，因为多数人"不擅长写文档但都会说话"。
- **会议的三级进化**：level 1 只出纪要 → level 2 会后 agent 主动办待办 → level 3 agent 入会、会上现场就办。
- **会议结束是工作的开始**：开完会 agent 直接去更新 CRM、项目系统、甚至修 bug——"开会是未来的 prompt"。

**【原理/要点】**
- level 1（当下大部分人）：用飞书妙记等出会后总结。这是起点。
- level 2：agent 不只总结，还**自己把待办办了**。会议成为"驱动 agent 主动工作的 prompt"——你不用写长 prompt，把会聊清楚、把妙记发它就够。
- level 3（讲者内部已体验）：agent **直接入会**，边聊边办。例如客户在会里提产品反馈，你当场问 agent"刚客户对这产品有啥反馈"，它实时基于发言逐字稿总结好发到消息里——不用等散会。

**【动手清单】**
1. 把**非超级敏感的会都录下来**，目的不是给你自己回看，是给 agent 当 context。
2. 给个人 agent 配工作流：每次会后有新妙记 → 自动产出三样东西——①**个性化总结**（基于它了解你的工作与关心点）②**你需要做的待办** ③**它可以干的待办**，然后你点名"你做一你做二"它就去干。
3. 进阶：把 agent 拉进会，让它实时读逐字稿，会上查数据、参与 brainstorm、现场总结。
4. **避坑**：别再花大力气雕 Prompt。把"在会上把事聊清楚"本身当成给 agent 的指令——聊天记录就是它的 PRD，日历/CRM 就是它的 context。

> ▸ 为什么摘这段：它把"怎么用 AI 开会"从"买个纪要工具"直接抬到"重构工作流"，且今天就能实现，是五个实践里门槛最低、回报最快的一个。

### 实践二 · AI-native 数据分析

**核心要点速览**
- **把 Excel 变成可交互 HTML**：拖动参数实时看结果（预算沙盘、报价配置器），比静态图/表强一个量级。
- **Agent 做归因的前提 = 业务 context**：数据突然跌了，"投放停了"这种原因不在任何看板里，在群/妙记/文档里。
- **把点连成线**：当 agent 能读你所有沟通/文档/会议，它才产生"以前很难实现"的全局分析效果。

**【原理/要点】**
- 可交互 HTML 是数据分析的"杀手级"形态：静态网页只能看，可交互网页能**推演**——拖融资额、拖投放，右边结果跟着动，直接给客户出定制报价。
- Agent 做基础分析已不错，但**做归因弱**，因为归因需要业务全局 context（"为什么跌了"的答案常在群里一句"投放停了"，看板里没有）。

**【动手清单】**
1. 拿一张你手头的 Excel（如预算/测算表），让 agent 做成**可交互 HTML**：关键变量做成滑块，右侧实时联动。
2. 给数据分析 agent 配一张"归因参考表"——把常见的业务背景（投放节奏、活动节点、口径变更）喂进去，让它做归因时有据可依。
3. 把分析 agent 接进你的沟通流（群/妙记/文档），让它"把点连成线"，而不是只盯着孤立看板。
4. **避坑**：别指望 agent 只看数据表就能归因。它看不到的那句"投放停了"，才是答案——**context 不全，分析必偏**。

> ▸ 为什么摘这段：直击财务/业财场景——你日常做经营分析、数据治理，最痛的就是"数对了但说不清为什么"。这段给出了"让 agent 读业务上下文"的具体解法。

### 实践三 · AI-native 招聘

**核心要点速览**
- **从沟通记录提炼人才画像**：让 agent 扫你跟下属/同事的一对一聊天、妙记，提炼你真正看重的素质，自动写 JD、筛简历、出面试题。
- **面试两轮法**：第一轮禁 AI 考专业硬实力；第二轮只能用 AI 考"驾驭 AI"的能力。
- **底层仍是 agent readable**：它看到你的 context，才招得准。

**【原理/要点】**
- 痛点：懂业务的不懂 AI，懂 AI 的不懂业务，难找两者兼具的人。
- 解法一（画像）：agent 读你日常给下属的反馈、提的要求 → 提炼你需要的**人才画像** → 写 JD、定筛选标准、筛简历、出面试题。
- 解法二（面试）：**第一轮不用 AI**，考无 AI 时的专业能力与现场反应；**第二轮只能用 AI**，现场给一个"没 AI 完不成"的任务 + 限时，且**聊天记录要留存**——你考察的不只是结果，更是"他怎么跟 AI 互动"。

**【动手清单】**
1. 让 agent 扫描你近期的 1:1 沟通/反馈记录，输出一份"我实际看重的能力清单"。
2. 据此让它起草 JD 与简历筛选标准（你审，不盲信）。
3. 面试 AI-native 岗位时，用"两轮法"：先裸考专业，再 AI 实战考协作。
4. **避坑**：别只看简历判断"会不会用 AI"——作品（做过的 skill/工作流）和"跟 AI 的互动过程"才说明问题。

> ▸ 为什么摘这段：招"既懂业务又能驾驭 AI"的人，是你这类岗位（高级财务、IPO 方向）组建团队时的真实难题，这段给了可执行的两步法。

### 实践四 · 团队级 Agent（同事级别）

**核心要点速览**
- **团队 agent ≠ 个人助理**：它是共享的、有团队级 context 的"同事"，拉进群自动获得权限与全局视角。
- **四个独有价值**：工作可接力 / 潜移默化的 AI 培训 / 参与 brainstorm / 服务上下游团队。
- **背后要做的基建**：权限设计 + 知识库设计 + memory/context 优化，且组织得改工作方式（尽量在群里聊，让痕迹对 agent 可见）。

**【原理/要点】**
- 行业趋势：Anthropic 把 Claude 无缝融进 Slack（非简单拉群，在 memory/context 上做了大量优化），让 Claude "基本相当于一个同事"。**未来 agent 一定越来越像同事，且必须融入日常协作**。
- 飞书/Ali 已支持"团队智能伙伴"：设角色定位/职责，拉进群自动获权，管理员控可用范围保安全。

**团队 agent 能做到、个人 agent 做不到的四件事**：
1. **工作可接力**：A 做完了，B 直接在下面接力纠偏，不用复制粘贴聊天记录。
2. **潜移默化的培训**：同事在群里怎么跟 agent 互动，你看一眼就学会了——"还能这么用"。
3. **参与 brainstorm**：你把 agent 拉进群，等于跟同事一起"共创给 agent 的 prompt"，沟通痕迹即指令，产出质量更高。
4. **服务上下游**：组织低效常来自团队间依赖（等下游排期）；共享 agent 能让上下游自己取用、加速。

> ▸ 为什么摘这段：个人 AI 容易让人"只跟自己的 agent 聊、人与人之间反而不交流"。团队 agent 把孤岛连起来，是"agent readable 组织"的真正落点。

### 实践五 · 在组织内打造 AI 学习氛围

**核心要点速览**
- **先干后学，而非先学后干**：直接落地场景做出来，再问 agent"你是怎么做的"——反向学原理。
- **渗透式学习 > 正式培训**：让 agent 只在群聊工作（不私聊），全员互相观摩怎么用 AI，像 Shopify 那样"所有人向所有人学习"。
- **装机活动破冰**：非技术部门卡就卡在"装不上"，现场一小时给全员装好能跑的 agent，后面纯聊天就会用。

**【原理/要点】**
- 传统教育"先打基础再应用"在 AI 时代应**反过来**：先不管怎样做出来，再做出来后问 agent 讲解背后的原理。
- **让懂 AI 和懂业务的人碰撞**：企业落地最大难点是"懂业务的不会 AI、懂 AI 的不懂业务"。创造场域（内部活动、FDE 驻扎业务部、装机活动）让两类人坐一起。
- **装机活动**：很多非技术部门用不起来，纯粹卡在"装不上 agent"这一步——只要装上了，后面就是聊天，不难。

> ▸ 为什么摘这段：组织层面的 AI 落地，卡点从来不是技术，是"人愿不愿意用、会不会用"。这段把"氛围"拆成了可办的活动。

### 收尾三感 · 落地心法（必看）

**核心要点速览**
- **AI-native 没有标准答案**：即使全球最领先的组织也在探索，业态/文化/工作方式差异太大，抄不来，只能自己长。
- **场景是"长出来"的不是"规划出来"的**：别先想终局再倒推，行业变化太快，只能大胆试、自然长。
- **别急于求成（生产力 J 曲线）**：新技术短期不升反降，需要学习/磨合/改流程的时间，长期必有巨大提升——要有耐心。

**【原理/要点】**
- **生产力 J 型曲线（productivity J-curve）**：新技术出现时，短期**不但不会提升效率，还会因学习成本、流程改造而下降**；但长期一定巨幅提升。历史上每次技术革命都如此——短期看不到效果完全正常。
- **实践是唯一方法**：讲者留的一句话——"实践是打造 AI-native 组织的唯一方法"，靠上课、靠学方法论都获得不了，每个人/公司都得走出自己的路。

> ▸ 为什么摘这段：这三感是"抗焦虑"的定心丸。你刚起步尝试 AI 落地，最容易因为"短期没看到大效果"而动摇——J 曲线告诉你这正常。

## 3. 最小可复现项目（照搬就能跑）

> 以下两个都是视频里讲者亲自演示/用的，直接复用即可，不绑定某个具体产品。

**项目 A · 把下一场会议变成 agent 的 context（门槛最低，今晚可试）**
- 目标：体验"会议结束 = 工作开始"。
- 步骤：① 选一场非敏感会录下来（或用现有妙记）；② 给 agent 下指令："每次我有新会议记录，给我三样——个性化总结 / 我需要做的待办 / 你能干的待办，然后直接去干"；③ 会后点名让它办一两件。
- 验收：你散会时，待办已经被它处理掉一部分。

**项目 B · 把一张 Excel 变成可交互 HTML（数据分析实践版）**
- 目标：把静态表升级成"能推演"的工具。
- 步骤：① 拿一张你常用的测算/预算 Excel；② 让 agent 做成网页，关键变量做成滑块，右侧结果实时联动；③ 拖动参数，看不同情景下的结果。
- 验收：你拖动一个参数，结论跟着变——这就是"可交互"的威力，比发静态截图强太多。

## 🔧 实践模块 · 上手任务

> 锚定你本次明确说的真实起点："**现在也在尝试落地的可能性**"。以下不编你的具体工作，只给可套的通用动作。

- **〔现象〕**：你已在主动探索 AI 落地，但尚处起步——最容易卡在"模型试了觉得一般、不知从哪下手"，正是讲者说的"context 没给够 / 没把信息对 agent 敞开"的典型阶段。
- **〔书中武器〕**：① 把 AI-native 重新定义为 **agent readable**——先别急着换模型，先让你的信息对 agent 可读；② 从"会议"这个最低门槛切进去（会议结束是工作的开始）；③ 接受"先干后学 + 短期 J 曲线下降"的心法，别因短期无效果动摇。
- **〔上手任务〕（今晚就能做的一个极小动作）**：挑你明天/最近一场例会，**默认开启录制/妙记**，结束后把记录丢给 agent，只下一条指令："给我个性化总结 + 我该做的 + 你能做的，然后直接去做能做的。"体验一次"会议即 prompt"。
- **〔30 天试验〕**：连续 30 天，每天做一件"把某段信息对 agent 敞开"的小事（一场会录下来 / 一张表变可交互 HTML / 让 agent 读一条群聊做总结），日记回写前后对比——重点观察：当你给的 context 变多，它的表现是不是真的变好。这本身就是对"agent readable"假设的验证。

## 知识拓展（陌生概念）

- **agent readable（对 agent 可读）**：企业信息对 AI agent 可见、可读取的状态。AI-native 的本质——不是模型多强，是 context 给得够不够。
- **会议 level 1/2/3**：1=出纪要；2=会后 agent 主动办待办；3=agent 入会、会上现场办。衡量"会议→执行"距离被压缩的程度。
- **团队智能伙伴 / 团队 agent**：共享的、有团队级 context 的 agent，像同事一样在群里工作；能做个人 agent 做不到的"接力、培训、全局视角"。
- **生产力 J 型曲线（productivity J-curve）**：新技术短期因学习/改流程成本导致效率下降（J 的左半边），长期才巨幅上升（J 的右半边上扬）。解释"为什么用了 AI 短期没见效"。
- **渗透式学习（Shopify 案例）**：Shopify CEO 让内部 agent 只在 Slack 群聊工作、不私聊，结果全员互相观摩怎么用 AI，"所有人向所有人学习"——无需课程表/培训计划的隐性培训。

## 金句深展开

- **"会议结束是工作的开始。"** —— 传统认知里，散会=沟通结束、执行另起。这句话把会议重定义为"给 agent 的启动信号"：会一散，agent 就去更新 CRM、布任务、修 bug。**力度在于它把"沟通"和"执行"两件事的时差压到零**，你不用再"开完会然后有空再弄"。落地启发：下次散会别急着关页面，先把记录交给 agent。

- **"实践是打造 AI-native 组织的唯一方法。"** —— 讲者收尾的原话。它直接否定了"找个标杆抄一下 / 上个培训课就能落地"的幻想。**力度在于它把 AI 落地从"知识问题"还原成"实践问题"**：每个组织业态、文化、工作方式太不一样，没有标准答案，只能自己在试错里长出来。落地启发：别再搜集"最佳实践"了，先开一场会被 agent 读，你就已经在路上了。

- **"场景不是规划出来的，是长出来的。"** —— 针对"先画终局再倒推"的规划癖。**力度在于它诚实承认"行业和技术变化太快，连下半年模型什么样都预测不了"**，所以倒推无效。落地启发：给你自己一个"敢试错"的许可，从小切口自然生长，而不是等一份完美蓝图。
