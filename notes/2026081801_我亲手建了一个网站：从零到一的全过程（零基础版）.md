## 1. 网站是什么？——三层结构

你访问 `https://irisinhere.github.io/irisshare/` 时，浏览器拿到的不是"一个网站"，而是**一堆文件**，分三类：

```
浏览器从 GitHub Pages 下载的文件
│
├── .html 文件（骨架/结构）   ← 首页、列表页、笔记页的"骨"
├── .css 文件（外观/皮肤）   ← 颜色、字体、表格冻结
└── .js 文件（行为/大脑）    ← 搜索、目录、登录、编辑
```

打开你的浏览器开发者工具（按 **F12** → 点 "Network/网络" 标签 → 刷新页面），你能看到浏览器到底下载了哪些文件。**这就是理解网站的第一把钥匙：眼见为实。**

你的网站文件长这样（`site/` 文件夹 = 仓库根目录）：

```
site/                        ← 仓库根目录（GitHub Pages 把它当网站根）
├── index.html               ← 首页
├── notes.html               ← 阅读笔记列表页
├── note.html                ← 单篇笔记阅读页
├── ai-finance.html          ← AI 财务列表页
├── assets/                  ← 资源文件夹
│   ├── css/                 ← 样式文件放这里
│   │   ├── site.css         ← 全站外壳样式（顶栏、卡片、按钮）
│   │   └── iris-note.css    ← 笔记正文样式（标题、表格、强调）
│   ├── js/                  ← 脚本文件放这里
│   │   ├── site.js          ← 深色切换、字号、目录抽屉
│   │   ├── md-render.js     ← 把 .md 翻译成网页（marked 翻译官）
│   │   ├── notes.js         ← 列表页渲染卡片
│   │   └── auth.js          ← 登录 + 在线编辑
│   └── img/                 ← 图片
├── notes/                   ← 你的笔记（.md 文件）都在这
│   └── manifest.json        ← 笔记目录表（自动生成）
└── tools/
    └── gen-manifest.js      ← 生成目录表的脚本
```

> **记这个结构**：以后你想改"什么东西"，先想它属于哪一类——外观找 `.css`，行为找 `.js`，内容找 `notes/` 里的 `.md`。

## 2. HTML 长什么样？——网页的骨架

`index.html` 的骨架（我简化给你看真实结构）：

```html
<!doctype html>
<html lang="zh-CN">           <!-- 整个网页的根，lang=语言 -->
<head>                        <!-- 头部：给浏览器看的信息（不显示在页面） -->
  <meta charset="utf-8">      <!-- 用 UTF-8 编码，中文才能正常显示 -->
  <title>IrisShare · A lifelong learner</title>   <!-- 浏览器标签页的标题 -->
  <link rel="stylesheet" href="assets/css/site.css?v=20260818b">  <!-- 引入 CSS -->
</head>
<body>                        <!-- 身体：页面里能看到的内容都在这 -->
  <header>顶栏（品牌+导航+按钮）</header>
  <main>主体内容</main>
  <footer>页脚（版权+自洽·自爱·自由）</footer>
  <script src="assets/js/site.js?v=20260818b"></script>  <!-- 引入 JS（放最后） -->
</body>
</html>
```

**两个要点**：
1. **标签成对出现**：`<html>` 开始，`</html>` 结束（斜杠 = 结束）。
2. **`?v=20260818b` 是什么**：这是"版本号"。GitHub Pages 有缓存（记得术语表吗），改完 CSS/JS 后浏览器可能还用旧文件。**加 `?v=新数字` 骗浏览器"这是新文件，重新下载"**。这是本网站"改了不生效"最常见的原因——不是没改对，是缓存。

## 3. CSS 怎么改？——标准格式与实操（重点）

### 3.1 CSS 的标准格式

CSS 的规则只有一种格式，**背下来，全文通用**：

```css
选择器 {
  属性: 值;
  属性: 值;
}
```

用"遥控器"理解：

| 部分 | 作用 | 例子 |
|---|---|---|
| **选择器** | 选"改谁" | `em`（所有强调） |
| **属性** | 改"哪个方面" | `color`（颜色） |
| **值** | 改成"什么" | `#b5482e`（砖红） |
| **分号 ;** | 每条规则结束 | 一句话的句号 |
| **花括号 { }** | 圈起一组规则 | 一个方案的文件夹 |

### 3.2 三种选择器（点名器）

你网站里这三种都用到了：

```css
/* ① 元素选择器：点名"所有某种标签" */
em { color: red; }                /* 所有 <em> 元素 */

/* ② 类选择器：点名"贴了某标签的元素"（类名前有 .） */
.cell-nowrap { white-space: nowrap; }   /* 所有 class="cell-nowrap" 的元素 */

/* ③ ID 选择器：点名"唯一身份证"（ID 前有 #） */
#noteBody { max-width: 860px; }         /* 只有一个，身份证号 */
```

还有**组合选择器**（更精确地点名）：

```css
.note-content em { color: var(--nc-em); }   /* 笔记正文【里面】的强调 */
```

意思是：先找到 `.note-content`（笔记正文），再找它**里面**的 `em`。空格 = "里面的"。

### 3.3 实操 1：把 `*强调*` 的砖红色改成别的颜色

你笔记里写 `*重要*`，浏览器会把它变成 `<em>重要</em>`，颜色由这条规则控制（这是你网站里真实存在的代码）：

```css
/* iris-note.css 第 44 行 */
.note-content em { color: var(--nc-em); font-style: normal; }
```

拆开看：
- `.note-content em` = "笔记正文里的强调"
- `color: var(--nc-em)` = 颜色用变量 `--nc-em`（这样深浅色主题会自动切换，见 3.4）
- `font-style: normal` = 不倾斜（中文没有斜体，倾斜会很难看）

**想改成绿色**，两种改法：

**改法 A（只改这一处，最简单）**：
```css
.note-content em { color: #2e8b57; font-style: normal; }   /* #2e8b57 是海绿 */
```

**改法 B（改变量，全站生效）**：找到变量定义（site.css 顶部）：

```css
:root {
  --em: #b5482e;   /* 浅色主题的强调色 */
}
[data-theme="dark"] {
  --em: #e0917a;   /* 深色主题的强调色（深色下用浅一点的红） */
}
```

把 `--em: #b5482e` 改成 `--em: #2e8b57`，所有用到 `var(--em)` 的地方一起变。

> **为什么用变量？** 因为"深色/浅色"两套皮肤要共享同一套规则，颜色抽出来当"旋钮"，换主题只换旋钮。这是 CSS 的进阶思维——**把会变的东西提出来**。

**颜色值有几种写法**（都见过吧）：

```css
color: #b5482e;          /* 十六进制：最常用，红绿蓝各两位 */
color: rgb(181, 72, 46); /* RGB：红绿蓝各 0-255 */
color: rgba(0,0,0,.45);  /* 加透明度，最后一个 .45 = 45% 不透明 */
```

### 3.4 实操 2：改表格——"首列冻结"是怎么实现的

你之前要求"宽表格首列冻结"，代码长这样（iris-note.css）：

```css
/* 首列：横向滚动时粘在左边不动 */
.note-content th:first-child,
.note-content td:first-child {
  position: sticky;   /* 粘住：滚动时保持原位 */
  left: 0;            /* 粘在容器左边缘 */
  z-index: 3;         /* 层级：别被别的内容盖住 */
  background: #fff;   /* 必须有背景，否则滚动时下面的内容会透出来 */
}
```

拆解：
- `th:first-child` = "表格第一行的第一个格"（th 是表头格，first-child 是"第一个孩子"）
- `position: sticky` = 这个网站的"魔法"之一，让元素滚动时"粘"住
- `z-index` = 层叠顺序，数字大的盖在数字小的上面

**想改**（比如背景色、阴影）：

```css
.note-content th:first-child {
  background: #f0f4fa;   /* 改成淡蓝底 */
  box-shadow: 3px 0 6px rgba(0,0,0,.3);  /* 右侧阴影更深，分界更明显 */
}
```

### 3.5 实操 3：手机端为什么会自动变？——媒体查询

你的网站在手机和电脑上排版不同，靠的是"媒体查询"：

```css
@media (max-width: 860px) {
  /* 当屏幕宽度 ≤ 860px（手机/平板竖屏）时，应用这里的规则 */
  .note-content { font-size: 17px; }        /* 手机端字号小一点 */
  .note-content h1 { font-size: 1.55em; }   /* 标题也缩小 */
}
```

翻译成大白话：**"如果屏幕窄，就执行这些规则"**。这是"响应式设计"的核心——同一套 HTML，在不同屏幕宽度下应用不同的 CSS。

## 4. JavaScript 怎么改？——语法与实操（重点）

### 4.1 JS 是什么

CSS 管"长什么样"，JS 管"会动"。你网站的动效全靠它：
- 点 ☾ 切换深色模式（site.js）
- 打字搜索笔记（notes.js）
- 展开/收起目录（site.js）
- 把 .md 翻译成网页（md-render.js）
- 登录 + 在线编辑（auth.js）

### 4.2 JS 的三个基础语法（够你读懂大部分代码）

**① 变量（存数据的盒子）**

```js
var theme = 'dark';        // 老式写法（你网站里用的是这种）
let count = 0;             // 新式写法
const MAX = 860;           // const = 常量，赋值后不能改
```

**② 函数（起名、可反复调用的步骤）**

```js
function 切换主题() {
  // 里面是"怎么切换"的步骤
  document.documentElement.setAttribute('data-theme', 'dark');
}
```

调用方式：`切换主题();` 或作为事件回调（下面讲）。

**③ 事件（门铃：用户操作才触发）**

```js
// 找到"深色切换按钮"，等用户点它，就执行函数
document.getElementById('themeToggle').addEventListener('click', function(){
  // 用户点按钮后要做的
  document.documentElement.setAttribute('data-theme', 'dark');
});
```

拆解这句真实代码：
- `document.getElementById('themeToggle')` = "在页面里找到 ID 是 themeToggle 的元素"（就是那个 ☾ 按钮）
- `.addEventListener('click', function(){...})` = "监听点击事件，点了就执行函数"
- `document.documentElement.setAttribute(...)` = "给整个网页设置一个属性"

**这就是 JS 的标准套路：找元素 → 绑事件 → 干事情。**

### 4.3 实操：读懂你网站里真实的一段 JS

md-render.js 里有一段"给表格套滚动容器"的代码，我把关键行拆开：

```js
tmp.querySelectorAll('table').forEach(function(t){   // ① 找到所有表格
  var w = document.createElement('div');              // ② 造一个新容器
  w.className = 'table-wrap';                         // ③ 给它贴个类名
  t.parentNode.insertBefore(w, t);                    // ④ 插到表格前面
  w.appendChild(t);                                   // ⑤ 把表格放进容器
});
```

| 行 | 干了什么 | 白话 |
|---|---|---|
| ① | `querySelectorAll('table')` | 把页面里所有表格找出来 |
| ① | `.forEach(...)` | 对每一个都做下面的事 |
| ② | `createElement('div')` | 造一个空盒子 |
| ③ | `className = 'table-wrap'` | 给盒子贴标签（CSS 靠它认盒子） |
| ④⑤ | 插到表格前后 | 把表格装进盒子里 |

**这段代码解决什么问题**：宽表格直接放页面上会撑破手机屏。给它套个"盒子"，盒子 CSS 设了 `overflow:auto`（超宽可滚动），表格就不会撑破页面了。

### 4.4 改 JS 的完整流程（你问的"手动更新"）

以"我想给笔记页加个'回到顶部'按钮"为例，完整流程：

**第 1 步：找到改哪个文件。** 笔记页的行为在 `md-render.js`（它管笔记正文的一切）。

**第 2 步：改代码。** 在文件末尾加：

```js
// 在笔记正文下方加"回到顶部"按钮
var backTop = document.createElement('button');
backTop.textContent = '↑ 回到顶部';
backTop.className = 'back-top';
document.body.appendChild(backTop);
backTop.addEventListener('click', function(){
  window.scrollTo({ top: 0, behavior: 'smooth' });   // 平滑滚回顶部
});
```

**第 3 步：本地验证（不上线就能测）。** 在电脑上起一个本地服务器：

```
（在 site/ 文件夹里打开终端）
python -m http.server 8099
```

然后浏览器访问 `http://localhost:8099/note.html?file=notes/xxx.md` 就能看到效果。**本地改、本地测，不影响的线上。**

**第 4 步：改版本号 + 推送上线。**

```
git add -A
git commit -m "feat: 增加回到顶部按钮"
git push
```

同时记得把 `note.html` 里的 `md-render.js?v=20260818b` 改成 `?v=20260818c`——**强制用户浏览器重新下载新 JS**（缓存坑，见第 2 章）。等 1-2 分钟，线上更新。

> **JS 改动的大坑**：语法极严格，少一个分号/括号，整个页面 JS 全挂。改完**务必本地先测**，别直接推线上。

### 4.5 出错了怎么看？——控制台（F12）

网页出问题时（比如"笔记加载失败"），**按 F12 → Console（控制台）**，红色文字就是报错。这是程序员的"故障灯"。

常见报错翻译：
- `Uncaught TypeError: xxx is not a function` = "xxx 不是函数"（多半变量名写错）
- `Failed to fetch` = "网络请求失败"（可能文件路径错、可能 CORS）
- `SyntaxError` = "语法错误"（少个括号/分号）

## 5. 内容怎么更新？——笔记的"身份证"与目录表

### 5.1 YAML 头（身份证）的真实格式

每篇笔记开头几行，就是 YAML。格式规则只有三条：

```yaml
title: 我亲手建了一个网站          # 键: 值（冒号后必须有空格）
author: Iris
tags: [网站, GitHub, CSS]          # 方括号 = 列表，逗号分隔
updated: 2026-08-19
```

规则：**键冒号空格值**；列表用方括号；**没有缩进层级**（顶层对齐）。

### 5.2 目录表 manifest.json 的真实样子

`notes/manifest.json` 长这样（真实截图，我截一个条目）：

```json
{
  "file": "2026081603_革命之路_电影解说_顾我.md",
  "book_id": "2026081603",
  "title": "革命之路（电影解说·顾我）",
```

**注意**：`.md` 是"人写的"，`manifest.json` 是"机器生成的"——你只管写 `.md`，脚本（gen-manifest.js）读它的 YAML 头，自动生成这个 JSON。**列表页读的是 JSON，不是 .md**。

### 5.3 生成目录表的脚本（node 是什么）

`tools/gen-manifest.js` 是一个 **Node.js** 脚本（Node 是"能在电脑上跑 JS 的程序"）。它的逻辑大白话版：

```
对 notes/ 里每个 .md 文件：
  读它的 YAML 头（身份证）
  取 title/author/tags/date 等字段
  把正文前 120 字当摘要
  组装成一个条目
把所有条目写进 manifest.json
```

在终端运行它：

```
node tools/gen-manifest.js notes
```

**为什么这里要 Node？** 因为生成目录表是"在服务器/电脑上批处理文件"，不是"在浏览器里显示"——两类 JS：跑在浏览器里的（md-render.js）和跑在电脑上的（gen-manifest.js）。

## 6. Git 命令——手动更新的底层操作

你平时"上传笔记"= 在 GitHub 网页拖文件。但真正的底层是 Git 命令，你也需要懂，因为**在线编辑和 Actions 都在用它**：

```
git status            # 看看现在有哪些改动（相当于"有哪些文件被动了"）
git add 文件名         # 把某个文件"放进待提交区"（git add -A = 全部）
git commit -m "说明"   # 存一个版本，备注写清"这次改了什么"
git push              # 把版本推到云端（GitHub）
git pull              # 把云端最新版拉回本地
git log --oneline     # 查看历史版本列表
```

你网站的完整发布流程，底层就是这三行：

```
git add -A
git commit -m "更新笔记"
git push
```

> **Git 的哲学**：永远不怕改坏——每次 commit 都是一个存档点，出问题 `git log` 找到旧版本，随时能回去。你平时不敢乱改的顾虑，Git 从根上解决了。

## 7. GitHub Actions——"机器人管家"的工作单

你已经知道 Actions 是自动机器人。现在看它的**工作单**（workflow 文件）真实内容，全站就这一份：`.github/workflows/update-manifest.yml`

```yaml
name: Update manifest                    # 工作单的名字

on:                                      # 什么时候触发？
  push:                                  # 当有人推送代码时
    branches: [main]                     #   推送到 main 分支时
    paths:                               #   且改的是这些路径时
      - 'notes/*.md'                     #     notes/ 里的 .md
      - 'ai-finance/*.md'                #     ai-finance/ 里的 .md

jobs:                                    # 要干什么活？
  update-manifest:                       #   （这活叫 update-manifest）
    runs-on: ubuntu-latest               #   在 Ubuntu 电脑上跑
    steps:                               #   步骤清单：
      - name: Regenerate manifests       #     第1步：重新生成目录表
        run: |
          node tools/gen-manifest.js notes
          node tools/gen-manifest.js ai-finance
      - name: Commit manifest changes    #     第2步：把新目录表提交回去
        run: |
          git add notes/manifest.json ai-finance/manifest.json
          git commit -m "chore: auto-update manifest [skip ci]"
          git push
```

**拆解**：
- `on.push.paths` = 触发条件：**只有 notes/ 里的 .md 变了才干活**（目录表变了不触发，防死循环）
- `steps` = 干活步骤，从上到下执行
- `run: |` = 后面是多行命令
- `[skip ci]` = 提交信息里带这个标记，告诉 GitHub"这个提交别触发机器人"（防自己触发自己）

**它的意义**：你以后在 GitHub 网页上传笔记 → Actions 自动更新目录表 → Pages 自动部署。**全自动，你只需要拖文件。**

## 8. 登录与在线编辑——真实的技术路径

你网站的登录不是传统"账号密码"，而是 **Token（手环）** 方案：

### 8.1 完整流程

```
你（浏览器）
  │ ① 点"登录"，输入 PAT（手环）
  ▼
auth.js：把 PAT 存进 localStorage（浏览器本地）
  │ ② 每次编辑，带上 PAT
  ▼
fetch('https://api.github.com/repos/IrisInHere/irisshare/contents/notes/xxx.md', {
  method: 'PUT',                       // 修改文件
  headers: { Authorization: 'Bearer ' + token },   // 出示手环
  body: JSON.stringify({ message: '说明', content: base64编码的内容, sha: '原文件指纹' })
})
  ▼
GitHub API 收到 → 改文件 → Actions 自动部署 → 网页更新
```

### 8.2 三个关键概念

**① API 是什么**：GitHub 开了一个"点餐窗口"（`api.github.com`），你用 HTTP 请求点餐：
- `GET` = 取东西（读文件、查用户）
- `PUT` = 放东西/改东西（更新文件）
- `POST` = 提交新东西

**② sha（文件指纹）**：每次保存要带 `sha`，它是"当前文件版本的指纹"。GitHub 用它判断：**改的是不是最新版**（防止两人同时改、互相覆盖）。好比改合同前先确认"你手上这份是不是最新版"。

**③ CORS（跨域限制）**：浏览器出于安全，默认**不允许**网页随便访问别的网站。GitHub 的 API 声明"允许所有人来"（`Access-Control-Allow-Origin: *`），所以你的网页能直接调它。但 GitHub 的**登录接口**没开这个权限，所以我们绕道用 Token。

### 8.3 为什么绕了个弯（真实踩坑）

最初想用 GitHub 官方"OAuth 登录按钮"（Device Flow），设计很优雅：
```
点登录 → 显示验证码 → 你去 GitHub 输验证码 → 自动登录
```
但实测失败：**GitHub 故意禁止网页跨站调用它的登录接口**（CORS），而你的静态网站没有自己的服务器可中转。于是改用 **PAT（手环）**：你自己在 GitHub 生成一个"限定权限的手环"（只能动 irisshare 仓库、只能改文件、可设过期），粘贴进网页。

> **教训**：不是所有方案第一次就通。**先试 → 测出问题 → 换方案 → 再试**，是"实现"的真实过程。你能从这个网站学到的最大技能，不是代码，是**拆问题和换方案的思路**。

## 10. 你现在可以动手的练习

学技术最快是动手。按顺序做这几个练习（都能在本地验证，不怕搞坏）：

1. **改颜色**：打开 `assets/css/site.css`，找 `--em: #b5482e`，改成 `--em: #2e8b57`（海绿），本地起服务器看 `*强调*` 变绿。满意再推线上。
2. **改字号**：`iris-note.css` 找 `.note-content { font-size: ... }`，把 `18px` 改成 `20px`，看正文变大。
3. **加注释**：在 `md-render.js` 任意位置加一行 `// 这是我自己加的注释`，保存刷新——页面无变化，但你明白了"注释不影响运行"。
4. **看报错**：故意把 `md-render.js` 里一个分号删掉，刷新页面，打开 F12 Console，看红色报错；改回来就恢复。（**看完记得改回来**）
5. **写一篇新笔记**：复制一篇 `.md`，改 YAML 头和内容，放进 `notes/`，运行 `node tools/gen-manifest.js notes`，本地看列表页出现新卡片。

每做完一个，你就比 99% 的人更懂自己的网站了。
