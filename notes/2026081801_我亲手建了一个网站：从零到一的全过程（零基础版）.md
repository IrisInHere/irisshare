# 我亲手建了一个网站：从零到一的全过程（零基础版）

> **写给看这篇文章的你**：如果你和我一样，之前从没写过一行代码，却突然发现自己"真的部署了一个网站、全世界都能访问"，那这篇就是为你写的。
>
> 这篇文章不教你怎么写代码，而是带你**用大白话看懂**：你每天用的这个网站，背后到底是些什么东西在配合工作。读完你会发现——**原来没那么神秘，原来每一样工具都只是为了解决一个具体的麻烦**。

## 0. 术语表（先读这里，遇到不懂的回来查）

技术圈的人聊天满嘴术语，其实每个术语背后都是一个**很朴素的日常道理**。我把本文会用到的词都列在这里，用"打比方"的方式讲清楚。

| 术语 | 它是啥 | 打个比方 |
|---|---|---|
| **网页 / HTML** | 浏览器能看懂的文字排版文件 | 一张"已经排好版的打印纸" |
| **浏览器** | 你看网页的软件（Chrome、Edge、手机自带的都算） | 一台"自动阅读机"：把文件读出来展示成页面 |
| **Markdown（.md）** | 一种"用符号标记重点"的写字格式 | 你写字时顺手画重点：`#` 是标题，`**` 是加粗，`*` 是变红 |
| **YAML 头** | 笔记最开头那几行 `标题/作者/日期/标签` | 笔记的"身份证信息"，贴在文章最前面 |
| **清单文件（manifest.json）** | 一张"笔记目录表" | 图书馆的"索引卡片柜"：每张卡片记一篇笔记的基本信息 |
| **渲染（渲染成网页）** | 把 Markdown 变成网页的"翻译过程" | 同声传译：把"人话"翻译成"浏览器的话" |
| **前端 / 浏览器端** | 在你设备上运行的部分 | 餐厅的"大堂"：你看到的、摸到的都在这里 |
| **后端 / 服务器** | 在别人机房运行的部分 | 餐厅的"后厨"：你看不见，但数据都从那儿来 |
| **静态网站** | 内容写死、谁看都一样 | 一本印好的书：每一页印出来就是那样 |
| **Git** | 一个"存档工具"，记录每次改动 | 游戏里的"存档点"：随时能回到任何一关 |
| **GitHub** | 存放代码/文件的"云端仓库 + 展示厅" | 网盘 + 公开橱窗的结合体 |
| **仓库（Repository）** | GitHub 上的一个项目文件夹 | 一个"云端资料柜"，里面放你的网站文件 |
| **提交（commit）** | 把一次改动"存档"下来 | 写稿后点一次"保存版本 v1" |
| **推送（push）/ 拉取（pull）** | 把本地改动上传 / 从云端下载 | 把草稿寄回云端 / 从云端取回最新版 |
| **GitHub Pages** | GitHub 自带的"免费网页托管服务" | 商场里的"免费展示柜"：把文件摆上去就能被看见 |
| **GitHub Actions** | GitHub 自带的"自动机器人" | 一个"自动干活的机器人管家" |
| **CSS** | 控制网页外观（颜色、字体、布局）的文件 | 房子的"装修设计图" |
| **JavaScript（JS）** | 让网页"会动"（点按钮、弹菜单、查搜索）的语言 | 房子的"电路与开关" |
| **API（接口）** | 程序之间"对话的窗口" | 餐厅的"点餐窗口"：你报菜名，厨房出菜 |
| **Token（令牌/PAT）** | 一串代表"你本人"的密码 | 商场的"会员手环"：戴上它，系统认得出是你 |
| **localStorage** | 浏览器在你电脑上留的"小纸条存储区" | 抽屉里的小便签：记住你的偏好，关浏览器也不丢 |
| **缓存 / CDN** | 为了让网页快，把文件"就近复制一份" | 超市在你小区门口设的"提货点"：东西提前备好，随时取 |

## 1. 这个网站到底是什么？

先说结论：**你建的这个网站，本质上就是一叠"有组织的文件"，放在一个"所有人都能参观的展示柜"里。**

你访问网址 `https://irisinhere.github.io/irisshare/` 时，实际发生的事只有三步：

```
1. 浏览器向 GitHub 的展示柜（GitHub Pages）说：我要看这个网站
2. GitHub 把对应文件夹里的文件发给你浏览器
3. 浏览器把文件"翻译成页面"，你看到网站
```

全程**没有任何一台"为你单独计算"的服务器在干活**——谁来看，看的都是同一批文件。这就是它不花钱、还能全球访问的原因。

**这是本文最重要的一句话**：网站 = 文件 + 一个能被人访问的展示位置。你学会的所有"部署"，都是在组织这两样东西。

---

## 2. 三个角色：你、文件、浏览器

这个网站里只有三个角色在配合：

| 角色 | 干什么 | 类比 |
|---|---|---|
| **你** | 用 Markdown 写笔记，上传文件 | 作者 |
| **文件（.md + 清单 + 样式）** | 保存内容和排版规则 | 书稿 + 印刷模板 |
| **浏览器** | 读取文件，展示成页面 | 印刷机 + 阅读器 |

你的工作流是：

```
写笔记(.md) → 放进仓库 → 推送到 GitHub → 全世界浏览器都能打开
```

**你真正做的，只是"写文件 + 放对地方"**——剩下的一切都是工具在自动化。现在开始逐个拆开看。

---

## 3. 为什么不用服务器？——静态网站与动态网站

可能你听过"服务器""后端"这些词，先分清两种网站：

- **动态网站**（如淘宝、微信公众号后台）：每次有人访问，服务器都"现场算一遍"再回给你——像餐厅后厨，有人点菜才现炒。
- **静态网站**（你的网站）：文件早就写好了，谁来访问都是把同一份文件发过去——像印好的书，摆在那谁看都行。

**你根本不需要"现炒"**：你的内容是笔记，不会因为访问者不同而变化。所以静态就够，而 GitHub Pages **免费**帮你把静态文件展示出去。

> 顺带解答一个常见疑问：为什么 GitHub Pages 免费？因为它只做"展示文件"这一件简单事，不用算、不用存数据，成本极低。简单的东西，自然便宜。

---

## 4. 你写笔记用的语言：Markdown

你可能会问：为什么不用 Word？因为 Word 文件里藏着一大堆"排版格式"，浏览器读起来麻烦，也不方便追踪"改了什么"。

**Markdown 的思路是：让"文字"和"排版标记"混在一起写，但标记很简单、人眼能直接看懂。**

比如你笔记里这些写法：

```
# 标题        ← 一级标题
## 小标题     ← 二级标题
**重点**      ← 加粗（蓝色）
*强调*        ← 强调（砖红色）
==关键洞见==  ← 高亮
| 列1 | 列2 | ← 表格
```

每个符号背后是一个"排版约定"。**你不用记命令，只需要记住"符号 = 意思"**——就像你随手用「⚠️」「⭐」标重点一样自然。

每篇笔记最顶上还有几行"身份证信息"（YAML 头）：

```
title: 我亲手建了一个网站…
author: Iris
tags: [网站, GitHub]
updated: 2026-08-18
```

这些不是给你看的正文，是给"目录系统"看的——它靠这些信息在列表页生成卡片。

---

## 5. 目录是怎么来的？——清单文件 manifest.json

网站有个"阅读笔记"列表页，上面整齐排列着每篇笔记的卡片（书名、作者、标签、简介）。这些卡片**不是手工做的**，而是靠一张"目录表"（manifest.json）生成的。

打个比方：

> 图书馆里，每本书除了书本身，还有一张**索引卡片**（书名、作者、位置）。读者想找书，先翻索引柜，而不是把整个书架翻一遍。

你的笔记列表页也一样：

```
你在 notes/ 文件夹放进一篇 .md
→ 一个自动脚本读它的"身份证信息"
→ 生成/更新 manifest.json（目录表）
→ 列表页照着目录表，自动摆出卡片
```

**你唯一要做的，就是"把 .md 放对文件夹"**，目录表由脚本自动生成（这个脚本我们后面讲 GitHub Actions 时再展开）。

## 6. 网页怎么显示笔记？——渲染与 marked"翻译官"

现在有个矛盾：

- 你写的是 `.md`（人话格式）
- 浏览器只认 `.html`（网页格式）

怎么办？靠一个叫 **marked** 的小工具——**它是你的"同声传译官"**：

```
.md 文件  →  [marked 翻译]  →  HTML 网页  →  浏览器展示
```

关键点是：**翻译是"实时"发生的**。每次你打开一篇笔记，浏览器现场翻译，不是预先做好一堆网页。所以——

> 你改一改 `.md` 存回仓库 → 别人刷新页面 → 看到的就是新内容。

**这也是"更新笔记 = 更新网站"这句口号的技术真相**：你改的是内容源（.md），翻译是自动的。

---

## 7. 文件存在哪？——Git 与 GitHub

你怕不怕"改坏了想退回上一版"？Git 就是解决这个问题的。

- **Git**：本地的一个"存档工具"。每次你做完改动，点一次"存档"（commit），它就记下这一版。出问题了，随时"读档"回任意一版。
- **GitHub**：把 Git 的存档"放上云"的地方。它既是你的**云端备份**，也是**公开橱窗**（别人能看）。

它俩配合的动作就三个词，你已经用得很熟了：

| 动作 | 人话 |
|---|---|
| `git add` + `git commit` | 把改动"存一个版本" |
| `git push` | 把版本"上传到云端" |
| `git pull` | 把云端最新版"拉回本地" |

> 你每天"更新笔记→上传→网页更新"，本质就是在做：**改文件 → 存版本 → 推云端**。

## 8. 网址从哪来？——GitHub Pages

文件放在 GitHub 上了，怎么变成"别人能访问的网址"？这就轮到 **GitHub Pages**：

> GitHub 说：你仓库里指定一个文件夹当"网站根目录"，我免费帮你摆到展示柜上，给你一个网址。

你的仓库根目录就是 `site/` 文件夹，所以：

```
仓库（irisshare）  →  根目录当网站  →  https://irisinhere.github.io/irisshare/
```

**神奇的地方在于**：每次你 `push` 新的改动，Pages **自动重新"上架"**——大约 1~2 分钟后，全世界看到的都是新版。你不需要做任何额外操作。

---

## 9. 自动干活的机器人：GitHub Actions

你之前有个麻烦：每上传一篇新笔记，还得手动更新一遍目录（manifest.json）。

解决方式很"程序员"：**雇一个不用睡觉的机器人（GitHub Actions）**，给它写一张"自动任务清单"（workflow 文件），规定：

```
规则：一旦 notes/ 文件夹里有 .md 文件发生变化
就执行：
  1. 自动跑脚本，重新生成 manifest.json（目录表）
  2. 把新目录表提交回仓库
  3. （然后 Pages 自动重新上架）
```

于是你的流程变成：

```
你上传 .md → [机器人自动更新目录] → [自动重新部署] → 网页更新
                         ↑ 全程无需你动手
```

**这就是"自动化"的本质**：把"固定套路"写成规则，让机器替你反复执行。

## 10. 网页的"装修"与"行为"——CSS 与 JavaScript

网站看起来好看、用起来顺手，靠两个文件：

**CSS = 装修设计图**（管"长什么样"）
颜色、字体、圆角、深浅色切换、表格冻结、目录栏……都是 CSS 在管。你提的"表格首行首列冻结"、"手机端自适应"，本质都是 CSS 里几条规则：

```
表头：滚动时"粘"在顶部不动
首列：横向滚动时"粘"在左边不动
手机端：表格超宽时，允许左右滑动而不是把页面撑爆
```

**JavaScript = 电路开关**（管"会动"）
点按钮切换深色、搜索笔记、展开目录、调节字号、登录、在线编辑……这些"点一下有反应"的事，都是 JS 写的。

一句话：**CSS 管"静态好不好看"，JS 管"动态灵不灵活"**。

## 11. 登录与在线编辑：一条走不通的路，换一条走通的路

你要求过"登录后能在线改笔记"。实现它绕了个弯，这里值得讲，因为**它最能体现"程序员遇到问题时怎么思考"**。

**第一条路：想用"GitHub 官方登录按钮"（OAuth Device Flow）**
本来设计得很好：点登录 → 出个验证码 → 你在 GitHub 输验证码 → 自动登录。
结果实测发现：**GitHub 故意不允许网页从别的网站"直接调它的登录接口"**（这叫 CORS 跨域限制，相当于"外卖不送到别的商场"）。纯静态网站没有自己的服务器，绕不开。

**于是换第二条路：Token（手环）方案**
- 你在 GitHub 生成一把"手环"（Fine-grained Token，可以限制它只能动 `irisshare` 仓库、只能改文件内容）
- 粘贴到网页 → 浏览器记住（localStorage）→ 之后每次编辑都戴着这枚手环去 GitHub 办事
- 权限可以精确控制：**只能改这一个仓库的文件，别的什么都碰不了**；也能设 1 年过期

**这个弯路的价值在于**：不是每个方案第一次就能跑通，**先试，测出问题，换方案，再试**——这才是"实现"的真实过程，和写文章改稿一个道理。

## 14. 结尾：从"不敢想"到"做到了"

我们回头看一开始那个念头："我不会编程，怎么可能部署一个网站？"

现在你知道答案了——**你不需要会编程**，你只需要：

1. 愿意用"符号写字"（Markdown，10 分钟学会）
2. 愿意把文件放进"对的地方"（一个文件夹）
3. 愿意点一次"上传"（一个按钮）
4. 剩下的，交给工具和规则

这个世界 90% 的"技术"，拆开看都是**为了解决一个具体麻烦而存在的常识**。你这次建站，已经亲手摸了一遍"文件 → 云端 → 展示 → 自动化"的完整链路——**这条链路，就是今天互联网的骨架**。

> 读书启发认知，实践影响行为。
> 你这次"实践"了一个网站，接下来可以更有底气地说：只要愿意拆解，任何"技术"都能被学会。
